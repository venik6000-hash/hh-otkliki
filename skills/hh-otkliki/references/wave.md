# Организация волны

Волна — пакет откликов, который агент готовит и отправляет по одному запросу человека.

Для небольшой волны достаточно одного исполнителя. Отдельный проверяющий агент полезен для первых писем, спорных фактов и приоритетных вакансий. Параллельных агентов запускай, только если среда это позволяет и объём оправдывает.

## Этапы и данные

| Этап | Что нужно | Результат |
|---|---|---|
| Сбор | Запросы из профиля, ID из реестра | Пул без повторов |
| Чтение | `vacancies/{id}.md`, фильтры, профиль | Задача найма, цитаты требований, вопросы, вердикт «берём / стоп / сомнение» |
| Выбор доказательства | Индекс выбора и границы из карьерной базы, детали выбранного кейса | Один аргумент, код кейса, ограничения |
| Письмо | Метод письма, текст вакансии, опора | Письмо и отдельно ответы на вопросы |
| Проверка | Вакансия, письмо, опора | `letters.py check` и смысловая проверка |
| Отправка | Разрешение, утверждённый текст, ответы, хэш резюме | Подтверждение отправки |
| Фиксация | Готовые материалы | Отчёт волны и строки реестра |

Текст вакансии скачивается один раз. Страницу вакансии в браузере открывает только отправщик.

Для однозначной фильтрации хватит недорогой модели. Неоднозначные требования, выбор аргумента и письмо требуют сильной модели.

## Рабочие материалы

Всё по волне лежит в `tmp/волна_{N}/`:

- `pool.json` — пул без повторов;
- `vacancies/{id}.md` — полные тексты;
- `cards/{id}.md` — карточки вакансий;
- `letters/{id}.md` — письма и ответы на вопросы;
- `бриф.md` — разрешение человека и заметки волны;
- `send_log.md` — лог отправки;
- `state.json` — стадии вакансий.

**Стадии** в `state.json`: `пул` → `карточка` → `письмо` → `проверено` → `согласовано` → `отправлено` или `пропущено`.

- Стадию ставь командой `python3 _tools/state.py mark <id>... --wave tmp/волна_{N} --stage <стадия>`.
- Для `пропущено` укажи `--skip-by чтение` или `--skip-by человек` и причину `--reason "..."`.
- Сводка: `python3 _tools/state.py show --wave tmp/волна_{N}`.

**Номер волны** = номер последнего отчёта в `волны/` + 1. Если отчётов нет, это волна 1. Номера не переиспользуй.

**Продолжение после обрыва:**

1. Если папка `tmp/волна_{N}/` есть и в её `state.json` остались незавершённые стадии, продолжай эту волну.
2. Вакансию в стадии `согласовано` без записи в `send_log.md` перед отправкой сверь по [hh-verify.md](hh-verify.md).
3. Разрешение человека бери из `бриф.md`.

## Карточка вакансии

- ID, компания, должность, дата публикации;
- главная задача найма;
- цитаты обязательных требований;
- формат и география;
- вопросы анкеты и кодовая фраза;
- вердикт с причиной.

## Опора письма

Опора — короткая выдержка для автора письма, не новая база. Состав:

- код кейса и раздел карьерной базы;
- личное действие;
- результат и его статус;
- что нельзя утверждать.

Передавай исполнителям пути к файлам, а не копию переписки. Отправщик не получает интервью, автор не получает историю всех волн.

## Стоимость и качество

- Записывай число повторов и правок писем.
- Дешёвый отбор выборочно проверяй по полным описаниям, особенно отказы и сомнения.
- Правила вкладок, подтверждения и сверки из [hh-send.md](hh-send.md) не зависят от модели и числа исполнителей.
