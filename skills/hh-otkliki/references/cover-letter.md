# Сопроводительное письмо: метод

Цель письма: дать работодателю проверяемую причину пригласить человека на разговор.

## Контекст и выбор аргумента

1. Выдели в вакансии главную задачу найма и обязательные требования. Учитывай вопросы и условия. Проблемы компании не додумывай.
2. Изучай сайт компании, только если без него непонятен продукт или вакансия приоритетная.
3. В `карьерная_база.md` прочитай «Индекс выбора» и «Границы достоверности».
4. Выбери один основной кейс. Второй допустим одной строкой, если он закрывает другое существенное требование.
5. Подробности читай только по выбранным кейсам. Если соответствия нет, пометь вакансию «сомнение».

Кейс выбирай по ответственности, а не по отраслевому ярлыку. Опыт в похожей отрасли слабее опыта решения той же задачи.

## Короткое письмо

Ориентир **600–900 знаков**, потолок **1100**. Короткое содержательное письмо не дополняй ради нижней границы. Длиннее — только по прямой просьбе работодателя.

1. Начни с короткого приветствия. Если работодатель просит кодовую фразу, поставь её первой строкой.
2. Первые 1–2 предложения после приветствия посвяти сделанному: какую задачу этого работодателя человек уже решал, действие, результат.
3. Держи первый содержательный абзац до 200 знаков.
4. Дай один аргумент: исходная ситуация, личное действие, подтверждённый результат.
5. Закончи простым приглашением к разговору или реально доступным демо.

**Запрещено:** начинать с пересказа вакансии. Примеры: «Вы ищете человека, который…», «Ваша задача мне близка», «В вашей роли нужно…».

**Запрещено:** обещать бесплатный аудит или работу до найма.

- Название компании в тексте само по себе не персонализация.
- Числа давай, только если они помогают оценить результат или масштаб.
- Ответы на обязательные вопросы анкеты держи отдельно от письма. Если форма одна, соедини их при отправке.

Тон спокойный и прямой, без саморекламы и лекций. Для небольшой команды можно разговорный, для корпорации нейтральный. Тон по умолчанию — в `профиль.md`. На англоязычную вакансию пиши на английском.

## Достоверность

- Пиши только факты из `карьерная_база.md` и подтверждённые слова человека. Не придумывай реплики заказчика, причины проблем, решения или результаты.
- Различай статусы: создано с помощью AI; AI работает внутри продукта; прототип; использовалось; используется сейчас; запланировано.
- Оценка сохраняет слово «примерно». Прогноз не становится достигнутым результатом.
- Корреляция показателя с набором изменений не доказывает эффект одного изменения.
- Не раскрывай названия NDA-клиентов. Обозначение клиента бери из карьерной базы.
- Отсутствующие навыки без запроса не перечисляй. На прямой вопрос отвечай честно.
- Обязательный отсутствующий навык не подменяй похожим инструментом.
- Удачные факты и закрытие можно повторять между работодателями. Частота кейса не повод выбирать более слабый.

Стиль: избегай длинного тире `—`, стрелок `→`, конструкции «не X, а Y» и канцелярских слов. Работодатели узнают по ним текст нейросети.

## Проверка

1. Запусти `python3 _tools/letters.py check <файл_только_письма>`.
   - FAIL исправь до показа человеку.
   - WARN — диагностика, переписывать не обязательно.
2. Проверь смысл:
   - аргумент отвечает на главную задачу вакансии;
   - у каждого утверждения есть код кейса, вклад и статус точны;
   - вопросы работодателя закрыты, условия не противоречат профилю;
   - текст понятен без расшифровки стека.
3. Если факта нет, убери его или спроси человека.

Обычно хватает одного черновика и одной содержательной правки. Не перефразируй по кругу.

**Внимание:** отсутствие FAIL не заменяет проверку смысла.

## След решения в отчёте

```
Задача: <одна конкретная задача вакансии>

Проверка: <длина; факты, статус и вопросы проверены; существенное ограничение либо «нет»>
> полный текст письма
```
