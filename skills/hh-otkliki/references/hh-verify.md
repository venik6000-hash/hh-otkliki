# Механика hh.ru: проверка отправки и сверка статусов

## Проверка отправки

Список откликов: `https://hh.ru/applicant/negotiations`. Там счётчик «Все N» и статусы.

1. Запиши счётчик до отправки.
2. После отправки подожди 5–8 секунд и проверь, что на странице вакансии есть «Вы откликнулись».
3. Сверь счётчик после волны. Если он вырос больше, чем на число вакансий, где-то ушёл второй отклик.

**Запрещено:** повторно отправлять при неясном результате. Сначала сверка.

## Данные кабинета

Возьми JSON из `<template id="HH-Lux-InitialState">` страницы откликов:

- `applicantNegotiations.topicList` — топики. Поля: `resumeId`, `lastState` (`RESPONSE`, `DISCARD`, `INTERVIEW`), `viewedByOpponent`, `creationTime`, `chatId`.
- `vacanciesShort.vacanciesList` — названия вакансий.
- `applicantNegotiationsCounters` — счётчики по статусам.

Список постраничный: `?page=N`. Основная вкладка показывает только активные топики. Отклики на архивные вакансии лежат на вкладке «Архив»: `?filter=archived&page=N`, у топика `archived: true`.

Порядок сверки:

1. Из вкладки hh выполни `fetch` каждой страницы обеих вкладок.
2. Разбери шаблон через `DOMParser`, собери все `topicList` и `vacanciesList` в один объект.
3. Сохрани объект в `tmp/negotiations.json`. Из JS-инструмента верни только счётчики, без хэшей.
4. Запусти `python3 _tools/registry.py update tmp/negotiations.json`. Скрипт обновит статусы в `реестр.md` и покажет расхождения.

## Сверка резюме

После первой волны допиши в `резюме_hh.md` resumeId каждого резюме: он есть у топиков в `topicList`.

После каждой волны сверь `resumeId` отправленных откликов с ожидаемым. Иначе отклик не тем резюме заметят только через несколько дней.

## Статус «собеседование»

**Внимание:** не верь статусу `INTERVIEW` на слово. Автосистемы части работодателей ставят его вместе с анкетой без участия человека. Живой интерес подтверждает только сообщение человека в чате отклика.

## Тексты отправленных писем

Отчёт агента — пересказ. Что реально ушло работодателю, бери из чатов откликов. Эндпоинт доступен из вкладки hh.ru:

```
https://chatik.hh.ru/chatik/api/chat_data?chatId=<chatId>&applicantId=<applicantId>&do_not_track_session_events=true
```

- `chatId` бери из `topicList`.
- `applicantId` виден в сетевых запросах при открытии любого чата.
- В ответе `chat.messages.items` первое длинное сообщение — сопроводительное письмо.

Раз в несколько волн прогони такую сверку целиком. Она ловит дрейф качества писем раньше, чем падение откликов.
